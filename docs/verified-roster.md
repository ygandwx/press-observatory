# 逐家验证档案与实测采集栏目

媒体详情的“公开资料核验”保存字段值、依据、核验日期和出处。持证名录可以证明某个账号在该期名录中的平台和运营主体。它不能单独证明今天仍能打开或允许自动采集。集团、报社、报纸、客户端和账号应分别核对。遇到重名、历史刊名或多个可能的运营主体，在检查记录中说明具体原因。原站快照、可维护字段和公开资料证据分别保存。

## 核验台账

每家有一个原站 UUID、机构名称、日期、逐字段检查说明和查阅路径。每条已证实的事实保存字段、值和证据 URL。一个机构在同一平台可有多个公开账号，证据列表保留每一条。上述数据由部署方在实例私有目录提供。导入会填写空字段，保留手工填写的值、原始档案和业务关联。相同文件重复运行应为零变更。首次关联自动填写的值，在原值未被维护人员修改时允许随新证据更新。

```bash
python manage.py verify_roster import /private/verified.json --expected 222
python manage.py verify_roster import /private/verified.json --expected 222 --apply
python manage.py verify_roster export /private/readback.json
```

## 栏目实测与定时

优先寻找承办机构、集团消息、社会责任报告、采编组织与经营公告等专栏。行业新闻综合首页单独记录。一个集团栏目只建立一个采集源。栏目可关联若干覆盖机构；采到集团消息时不会自动归为每家成员报社的事件。

可复用的[首批公开栏目配置](../deploy/public-sections.json)包含发布方、栏目路径和选择器，部署时仍需按本机实测结果核定定时名单。清单包含名称、URL、直接所属机构或覆盖机构、文章链接选择器、路径前缀、本批上限、最小间隔和栏目专用标题词。可设置经实测的正文标题、正文和发布日期选择器。日期缺失时保留空值。每日、每周和每天两次的调度分别使用北京时间 08:00、周一 08:00、08:00/18:00 两个基础窗口。

```bash
python manage.py manage_sections /private/sections.json
python manage.py manage_sections /private/sections.json --apply --trial-key 20261118-review
python manage.py manage_sections /private/sections.json --apply --schedule
```

相同批次键重复投递复用同一任务。每一来源先处于手动启用状态。只有清单注明可定时、当前配置实测成功、命中且确实产出过原文的栏目才纳入计划。维护人员可在信源配置取消“纳入定时采集”或停用。低频或历史专栏可保留手动。公开来源的工作进程对每次清单、正文、跳转及重试执行以下检查。

- 按来源主机校验证书和公共地址。跨站跳转、传输降级、验证码以及不能核验的正文结构均须人工复核。
- 每轮获取本主机 robots.txt。200 需解析为明确规则，直接 404/410 按未发布规则处理。跳转、权限拒绝、伪装为 200 的 HTML 和无法解析的频率要求暂停该源。
- 在 PostgreSQL 记录每个主机的上次请求时间和等待期限。多个 worker 共用同一间隔，按栏目间隔、Crawl-delay 和 Request-rate 取严格者。429 或暂时性网关错误遵守 Retry-After，短等待最多重试一次。超出本次等待上限的来源暂停。
- 文章 URL 规范化后去重。完成状态、命中、待审、新增、重复、规则过滤和失败从实际任务读取。栏目能打开、任务完成或登记了一条官网本身都不能计为贡献原文。

源配置与定时报名由维护人员控制。公开业务栏目登记为非可信自动批准源，在本机正式实例中还保持全局自动批准关闭。证据可分别从 `Media.verification`、`Run.counts`、`Run.crawl_evidence` 及实际 `Article.source` 回查。

## 2026-11-18 核对结果（UTC）

222 个原站标识均已建立查阅记录，220 家获得 1,418 条独立字段证据。“传媒行业媒体”和“传媒期刊”是不能唯一识别出版单位的泛称。共查证 186 个官网入口、130 项客户端、161 项官方公众号、116 项视频号及 15 项海外账号，覆盖 212 家机构的 608 个机构渠道字段。共享客户端和集团入口注明实际运营关系。原始档案保持独立并通过逐项回读。

本轮实际接入 13 个经过小样本验证的栏目，其中 10 个参加定时，3 个保留手动。既有来源计入后，正式实例有 18 个配置源、15 个启用源、12 个定时源、16 个曾完成任务的不同来源，以及 15 个贡献过原文的不同来源。

新增 25 篇均进入待审。站点证书、robots 跳转至 HTML、跨站去微信、历史栏目与缺少静态正文链接分别留档。人民网首页实测执行 120 秒间隔，媒体相关入口跨主机；光明网首页的相关原文已由现有报网动态覆盖。两个首页维持停用，国家新闻出版署业务动态暂未接入。

## 第二次逐家核对

首轮剩余的 24 家候选涉及 17 个不同栏目。第二次核对同时查阅 222 家机构的主管部门、出版单位、采购公示、预决算和年度社会责任报告。机构台账分别记录实际查阅范围、已取得的材料、停止原因和再次核验所需条件。正式导入时保留原站 UUID、账号、人工审核决定和原始档案。

经复核撤回的主张进入修订记录。导入器只清理曾由其填写、仍与其上次写入一致、并在修订记录中明确撤回的字段值。集团共用、历史停用及其他关联渠道可单列关系、依据和来源。相同输入可重复导入。

第二批栏目可使用[公开配置](../deploy/verified-sections-followup.json)重做小样本。发布方混合的栏目先按主体词筛选清单，再执行行业相关性和去重规则。部分网站在正常 HTML 内发布 JSON 清单和正文元数据，适配器读取这些结构并验证正文。对缺少可信证书、要求验证或拒绝采集请求的站点，保留现有访问限制。

年度目录保持手动。每篇候选必须仍出现在公开目录中，使用已核验的 HTTPS 原文地址、标题、正文选择器及发布机构。读取原文时按该目标主机单独检查 robots 和请求间隔，跳转仍限于该主机。标题与核定材料不一致时留待复核。多机构目录按每篇已核验的出版单位关联事件。重复 URL 沿用原记录。
