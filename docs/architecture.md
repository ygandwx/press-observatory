# 技术与数据设计

## 运行结构

浏览器使用 React、TypeScript、Vite 和 ECharts。Django REST Framework 提供同源 JSON API；Django 会话承载身份，CSRF 校验覆盖登录及后续写操作。Gunicorn 运行网页服务，WhiteNoise 提供构建后的前端资源。PostgreSQL 保存业务记录及采集队列。网页、单独的 worker 和迁移命令使用同一套 Django 模型。部署命令见[运行手册](operations.md)。

| 数据 | 关系及行为 |
| --- | --- |
| Media、Source、Rule、Policy | 档案包含主管单位、地区、分类、垂直领域与五件套。信源关联机构和适配器。主体、动作和排除词独立管理；自动批准默认关闭。 |
| Article、Event、Change | 原文 URL 规范化后唯一，文章保留链接核验状态。事件关联多个来源和机构。归并保留子事件、文章与操作记录，拆回后可独立统计。编辑、审核、归并用版本号或数据库行锁控制竞争。 |
| Run | 手动请求幂等键或北京时间调度窗口与信源组成任务唯一键。工作进程短事务领取、网络请求在事务外执行、租约过期可重领。写入结果校验租约。状态、进度、尝试次数、计数、失败原因供前台轮询。 |
| Report、Edition | 类型和业务日期唯一；周报按周一起始日期归档。草稿保存生成时的来源和事件内容；签发形成独立快照。分享由不可猜测令牌定位，可撤销。 |
| 用户及关注关系 | 阅读、编辑、审核、签发、配置五项权限可组合授予。收藏和机构关注按用户区分；所有 API 从当前会话检查资格。 |

## 主要接口

相对路径以 `/api/v1/` 为基准；分页支持 `page` 与 `size`，返回 `count`、`page`、`size`、`items`。

| 接口 | 操作 |
| --- | --- |
| `session`、`login`、`logout`、`ready` | 会话及分类字典、会话登录、退出及数据库就绪探针 |
| `dashboard`、`events`、`events/{id}` | 看板分布及趋势、动态分页/导出、人工录入、详情、标星、核验、编辑、归并和拆回 |
| `events/review`、`events/search` | 事务内批量审核；按当前可见范围进行模型语义筛选 |
| `media`、`media/{id}` | 机构检索、档案编辑、渠道缺项与变化历史；同业对比复用详情 |
| `monitor`、`monitor/{action}` | 概览与日志，维护 source/rule/policy，collect/retry/inspect 投递和处置，extract 为待核验的录入草稿提供模型建议 |
| `reports`、`reports/{id}`、`shared/{token}` | 列表与生成、编辑、提交签发、更正与版本、分享和撤销；公开接口只读签发内容 |

## 采集策略

定时或手动投递 → HTML/RSS/授权数据接口 → 主体与动作词双命中并检查排除词 → 读取原文 → 结构化模型建议 → 过滤、待审或自动入库。可信信源、可读原文、阈值和近似标题检查共同决定自动放行。模型不可用时可人工编辑、核验和审核。覆盖面由实际配置的来源决定。

受限平台按信源 ID 接入运营方提供的授权 JSON feed。没有授权时生成巡检任务。通用 HTML 适配器按同域链接采集，每次最多 30 个候选；语义检索将所选范围最近的最多 200 个事件交给配置的模型。更大规模的专业索引、专属平台开发者 API 与跨语种模型评测都依赖部署方的真实语料和接入条件。
