# 开发路线与交付状态

项目按“信源 → 原文 → 事件 → 审核 → 观测与出版”组织。看板和期刊都依赖可复核的事件，因此先建立机构、来源和审核流程，再开发统计和编辑页面。

| 阶段 | 依赖与主责 | 工程交付与验收 | 当前状态 |
| --- | --- | --- | --- |
| M0 项目准备 | 工程主责、业务编辑 | 定名称与技术栈，约定事件统计、归并、签发权限，建立工程与验收文档 | 主分支已有立项材料和协作模板 |
| M1 开发环境与身份 | M0，工程 | 同源前后端、数据库迁移、会话和权限、就绪探针、CI。从干净检出可启动，匿名访问和越权操作被拒绝 | 草稿 PR 已实现，有 Compose 启动检查 |
| M2 名册、原文与审核 | M1，工程和编辑 | CSV 先预检再导入，编辑核验原文，审核人归并或拆回，保留操作者、版本与多份来源 | 导入、审核、归并和拆回已验证。正式名册待业务方提供 |
| M3 采集与任务执行 | M2，工程和运营 | 独立 worker 接受定时及手动任务，重试无重复入库。运营可定位单个信源的失败并转人工巡检 | 公开信源与独立 worker 已验证。受限渠道待授权联调 |
| M4 看板、动态、档案、日报 | M2 和 M3，前后端与编辑 | 八类事件可筛选，卡片与下钻同一快照。日报按六栏选材，可核对出处并签发、导出和撤销分享 | 已验证旧链接经归并和拆回后仍可重查、归栏证据与历史签发稿 |
| M5 模型辅助与周报 | M4，工程和业务编辑 | 完整筛选范围分批检索。编辑用标注样本核对误收和漏收，再决定自动入库阈值。一个完整自然周的两版简报可追溯到同组事件 | 523 条检索及双版本周报逻辑已用隔离样本验证。真实模型质量和完整观测周待评阅 |
| M6 试运行与发布 | M4 起可并行演练，发布依赖 M5 和目标环境，运维与业务负责人 | 目标机部署及 HTTPS、定时器、告警、备份恢复和版本回退。编辑核对一期实际日报和一整周简报 | 已提供部署手册，独立库完成恢复验证。生产环境联调与发布待安排 |

## 正式试用的验收顺序

1. **业务编辑**整理正式机构名册与信源授权范围。对“地方商业报”“晚报类”补充可核验的归栏资料，保留缺项清单。
2. **工程和运营**在试用环境导入经预检的名册，配置授权模型与渠道，核对采集用时、失败原因和重试结果。
3. **业务编辑和审核人**按一个完整自然周走通采集、复核、归并、日报签发和周报评阅。用同一批人工标注样本评估模型质量。
4. **运维**记录构建提交与迁移版本，在独立环境恢复并抽查事件来源、签发版本和审计记录，再在目标机演练升级与回退。

工程验收记录见[功能对照](../README.md)和[可重复的业务场景](acceptance.md)。开发接口、启动、备份与恢复命令见[架构](architecture.md)和[运行手册](operations.md)。
