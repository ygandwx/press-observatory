# 开发路线图

## 交付目标与排期假设

以一名全栈工程师主责、一名业务编辑参与验收、单台 Ubuntu 服务器为估算基础。下表是净开发工作日，不含等待服务器、样本核验或渠道授权的时间。阶段按验收结果推进。M1–M4 预计 16–24 个工作日到内部试用，M5–M6 再用 9–14 个工作日达到首版发布条件；周报验收另需覆盖一个完整业务周，观察期可与 M6 并行。

| 阶段 | 前置条件 | 交付物 | 退出条件 | 估算 |
| --- | --- | --- | --- | --- |
| M0 项目准备 | 空仓库 | 项目入口、技术设计、验收案例、任务与 PR 模板 | 本地文档检查通过，团队可从 M1 任务表开工 | 本次交付 |
| M1 可运行的开发环境 | M0 | React/Vite、Django/DRF、PostgreSQL、开发 Compose、迁移、登录、就绪探针和 CI | 从干净检出按 README 一次启动；数据库迁移成功；前端显示后端就绪；匿名及已登录访问测试通过 | 3–4 天 |
| M2 机构、来源与人工审核 | M1；业务方提供一个真实案例 | 名册导入预检、机构与信源档案、文章与事件、审核队列、可撤销归并、审计 | 重复导入无重复机构；两篇来源可归为一件并可拆回；无来源或无审核权的写入被拒绝 | 5–7 天 |
| M3 采集与任务运行 | M2；至少一个可访问且允许采集的官方信源 | 首个官网适配器、任务队列、定时和手动投递、重试、失败详情、人工补录 | 对同一输入重跑无重复记录；重启 worker 可续跑；网页请求不等待采集；运营能定位到单个失败信源 | 4–6 天 |
| M4 领导端与日报试用 | M2、M3；已核验历史事件或当期新增 | 响应式看板、八类入口、动态列表和详情、机构时间线、日报生成/编辑/签发/历史 | 跑通 README 中的双来源案例；指标和列表一致；已签发期次可复现；编辑与签发权限逐项验收 | 4–7 天 |
| M5 AI 辅助与周报 | M4；可用模型或经批准的测试端点；周报具备一周数据 | 结构化抽取、去重候选、自动入库策略、运营覆盖度/补全、领导版与业务版周报 | 在编辑标注的同一批样本上报告误收、漏收和疑似错并；编辑确认阈值后才开启自动放行；周报两版结论可回溯到同组事件 | 5–8 天 |
| M6 试运行与发布 | M4 可先开始部署演练；正式发布依赖 M5 | Ubuntu 部署手册、备份与恢复、健康告警、日报导出/只读分享、发布记录 | 在独立环境恢复一次备份；演练升级与回退；外部只读链接只展示授权版本且可撤销；业务方验收一个完整观测周期 | 4–6 天 |

## M1 首批可领取任务

按任务编号开 Issue。每项任务在 PR 中附上可复现的验收记录。负责人按岗位列出，具体人选在开工时分配。

| 编号 | 主责 | 任务与依赖 | 完成证明 |
| --- | --- | --- | --- |
| M1-01 | 后端 | 初始化 Django、DRF 与 PostgreSQL，加入依赖锁文件、配置样例、初次迁移和就绪接口 | 空库可迁移；数据库在线时探针返回成功，断开时就绪探针报告不可用 |
| M1-02 | 前端 | 初始化 React/TS/Vite，建立导航、空态和错误重试；可与 01 并行 | 能构建；对接 01 后就绪状态来自真实请求，后端不可用时能重试 |
| M1-03 | 后端 | 依赖 01；建立 session 登录、四项业务权限与审计基础字段 | 测试覆盖匿名、只读、编辑、审核和签发；修改接口同时验证会话、权限及 CSRF |
| M1-04 | 全栈 | 依赖 01、02；编排 web、API、DB，补齐环境样例、启动/停止和初始化说明 | 第二个人从空目录按 README 启动；重启后数据保留；仓库中无部署密钥 |
| M1-05 | 交付 | 依赖 01–04；把构建、迁移、权限与接口冒烟测试接入 PR 检查 | 从干净检出执行 CI 通过；有意破坏权限断言时检查失败 |
| M1-06 | 业务编辑 | 并行准备经核验的机构及双来源案例，明确文章发布日期与拟入库日 | 在内部资料库交付原始链接、核验日期、预期分类；仓库只记录样本编号 |

每个阶段关闭前，由工程主责演示一条成功路径与一条失败或重试路径，由业务编辑核对术语、数量和出处。新需求记录为后续任务并标注影响的阶段。

## 依赖和范围调整

- 缺正式名册时，M1 和 M2 的导入器及约束测试可先行；业务验收使用经核验的来源。导入前按名称别名、主管单位与地区预检并输出冲突清单，待编辑确认后再写库。
- 某信源限制访问时，记录失败原因并开放人工链接录入；优先在可访问的官方信源完成 M3。公众号、短视频及第三方商业数据接入单独立项，依据授权和成本安排。
- 模型或预算未就绪时，M4 可用人工核验的事件出日报。M5 的模型接入、评测与自动入库开关独立验收。
- 单机容量和备份存储位置在 M6 前确认。技术主责记录采集时长、队列积压、失败率与数据库容量，再决定是否增加 worker 或迁移数据库。
- 发布后优先按积压和误收实测值优化采集。企业 SSO、更多开放平台、订阅推送进入后续版本评估。
