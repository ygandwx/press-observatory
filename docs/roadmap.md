# 完整交付与验收

开发按依赖连续进行，统一以六个业务模块能运行、数据能追溯、权限与发布路径能验证为交付条件。

| 工作面 | 依赖 | 验收结果应包含 |
| --- | --- | --- |
| 运行与身份 | Python、Node、数据库 | 可复现构建、数据库迁移、会话登录、服务端权限 |
| 新闻资料与审核 | 机构、信源、文章、事件模型 | 多来源、退回理由、归并和拆回、审计、重复操作 |
| 监测与模型 | 公共信源，模型功能需凭据 | 队列进度、去重、失败和人工巡检、自动策略 |
| 领导端 | 已批准事件与媒体档案 | 卡片与列表同口径、组合筛选、分布趋势与来源 |
| 出版 | 已批准事件与核验来源 | 日报和双版本周报、签发快照、导出、撤销分享 |
| 运行验证 | 独立测试库与浏览器 | 测试、构建、窄屏、权限和重启记录 |

内部样本保存在部署方受控存储。此前 Issue 编号用于追踪工程依赖，不设分期审批。具体接口及验收场景见[业务口径](acceptance.md)与[架构](architecture.md)。
