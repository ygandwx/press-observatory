# 业务口径与验收场景

## 观测范围

收录以媒体机构、报业集团或行业主管部门为主体的改革发展动态。编辑根据事件主体与实际行动判断相关性。例如报社上线采编平台可收录，报社报道医院上线诊疗平台应过滤。八类事件沿用改革、业态、技术、数据、政策、阵地、人事、其他；每个事件设置一个主类，可另带趋势标签。媒体层级、机构类别与事件类别是独立字段。

## 指标定义

| 指标 | 统计口径 | 下钻目标 |
| --- | --- | --- |
| 今日入库 | 首次批准时间落在北京时间当日，且在查询截止时有效、已批准的唯一事件数 | 已批准事件，按首次批准时间过滤 |
| 今日发生 | 发生日期等于业务日的有效已批准事件；日期未知单列 | 已批准事件，按发生日期过滤 |
| 待审核 | 截止时刻处于待审状态的候选事件数；仅授权人员可查内容 | 同一权限范围的审核列表 |
| 分类动态数 | 在页面标示期间和批准范围内，按事件主类计唯一事件数 | 原区间、原分类、原可见范围 |
| 媒体档案数 | 当前在库且有效的唯一机构数；占位与待核验记录单列 | 相同档案范围 |
| 自动入库占比 | 所选期间首次批准且以自动方式入库的有效事件数 ÷ 同期首次批准的有效事件数 | 展示分子、分母及对应条件；分母为零显示“暂无入库” |

统一查询截止时刻与业务时区，明确区分来源发布日期、事件发生日与批准时间。归并或撤销会改变当前结果。对需要保持一致的卡片下钻，查询按同一截止时刻还原有效状态或使用同一快照标识。期刊发布读已签发版本。

## 权限基线

| 操作 | 默认授权 | 验收要点 |
| --- | --- | --- |
| 阅读已批准事件、机构档案及已签发报告 | 社领导、运营 | 只读账号直接调用修改接口也应被拒绝 |
| 采集、补录、编辑草稿和提交归并候选 | 编辑 | 记录操作者；待审记录在领导列表不可见 |
| 批准、退回、确认归并及拆回 | 审核人 | 退回必填原因，归并保留来源，状态冲突可见 |
| 签发和发布更正版 | 签发人 | 保存签发身份、时间、版本和快照 |
| 信源配置、自动策略、账号授权 | 获授对应管理权限的人 | 管理权限单独授予，变更有审计 |

同一人可兼任多项职责。前端根据权限显示入口，后端逐项验证。可读草稿、能否签发等权限以业务身份授权为准。

## 可重复的验收场景

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| A01 采集重试 | 在处理已写入文章后中断并重启 worker，再次处理同一任务 | 一篇来源文章，完整尝试记录，任务有最终状态 |
| A02 跨渠道归并 | 一个报社官网和数字报各发一篇同事件文章，审核后归并 | 两条来源可打开；一个有效事件；该机构档案和对应卡片各增加一件 |
| A03 误并恢复 | 将两件相似但独立的事件合并后拆回 | 来源恢复到正确事件，统计与列表同步，操作者可追溯 |
| A04 日期边界 | 提供昨日发生、北京时间今日零时首次批准的事件 | 今日入库计一件；今日发生不含该件；下钻和分页总数一致 |
| A05 并发审核 | 两个审核人以同一版本先后提交不同结果 | 一次生效，后一次提示冲突；不重复入库 |
| A06 角色边界 | 用只读账号尝试签发，用仅有编辑权限的账号尝试批准 | API 拒绝，数据不变；获授对应权限的账号可完成并留下记录 |
| A07 出版复现 | 签发日报，再修改事件摘要或归并来源 | 已签发快照保持原文和计数；更正另留版本 |
| A08 失败可见 | 模型超时或返回不完整字段，或抓取链接失效 | 有错误分类和可重试记录；未经核验的信息进入待审；页面区分失败与零数据 |
| A09 前端可用性 | 在 375、768、1440 像素宽度打开看板、列表及日报；模拟空数据与未知标签 | 导航、筛选可用，无整页横向溢出；空态与未知标签可读 |
| A10 分享与恢复 | 撤销签发版只读链接；在独立环境恢复数据库备份 | 旧链接失效，草稿不外泄；恢复后按期号还原报告、引用及审计记录 |

自动测试使用明确标注的合成样本，验收演示使用编辑核验过的真实链接；分别保存结果。上线前由业务编辑确认数据范围，由工程主责记录构建版本、迁移版本与验收结论。
